# AgentShield test manifest — the SINGLE source of truth for what tests exist,
# which layer they run in, and which functional areas they cover.
#
# Format (pipe-delimited, 4 columns):
#   layer|groups|file|title
#
#   layer   api      — bash suite under scripts/e2e/, kubectl-execs into a pod.
#                      Tests the HTTP API only. Cannot catch a broken screen.
#           browser  — Playwright spec under studio/e2e/, drives the real deployed
#                      Studio in Chromium. The only layer that proves a UI journey.
#   groups  comma-separated functional areas. A test may belong to several — the
#           point is that "what should I re-run after touching X" has one answer.
#   file    path relative to scripts/e2e/ (api) or studio/ (browser)
#   title   human label printed by the runner
#
# Run with scripts/run-tests.sh:
#   bash scripts/run-tests.sh --groups                 # list functional groups
#   bash scripts/run-tests.sh --list --group tools     # what would run
#   bash scripts/run-tests.sh --group tools            # both layers, tools only
#   bash scripts/run-tests.sh --layer browser          # every browser test
#   bash scripts/run-tests.sh --layer api --group hitl,workflow
#
# Adding a test? Add its line HERE. The runners have no other registry — a test
# missing from this file will not run in any group, and scripts/run-tests.sh
# --audit fails if a suite/spec file on disk has no manifest line.
#
# ---------------------------------------------------------------------------
# Functional groups
#   agent       agent CRUD, versions, classes, creation flows
#   chat        playground, consumer chat, conversations, feedback
#   cost        cost attribution and rollups
#   debug       scratch/probe specs — excluded from group runs by default
#   deploy      deployment lifecycle, overview, GC, drift, credentials
#   eval        eval gate, eval runner, eval v2
#   execution   execution shapes, triggers, scheduler, event gateway, daemons, webhooks
#   governance  safety, OPA, quarantine, isolation, machine identity
#   health      platform health, observability, alerting, resilience, smoke
#   hitl        human-in-the-loop approvals, authority, resume
#   knowledge   knowledge bases, RAG, KB bindings
#   memory      agent memory, context storage, TTL/isolation
#   rbac        role/permission model and artifact delegation
#   tools       tool registry, schema build, tool metadata, tool pickers
#   workflow    composite workflows, orchestration modes, workflow runs
# ---------------------------------------------------------------------------
